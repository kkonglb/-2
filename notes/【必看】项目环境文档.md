如果部署之后，存在**<font style="color:#DF2A3F;">【页面无响应】、【访问之后页面白屏】</font>**现象，按照下列解决方法解决：

### 常规法
检查当前 nodejs 版本，即在 cmd 中通过 node -v 查看，是否是16.14.0版本。

如果是，**<u>重新解压资料包</u>**，再次执行 npm i 即可，等依赖拉回来之后，再执行 npm run dev 运行。

:::success
注意：最好最好不要将前端项目解压在还有中文的路径下，要放进一个纯英文路径。

:::

如果不是，可通过 nvm 版本管理工具切此版本，或者卸载重装此版本。**<font style="color:#000000;">如果觉得麻烦，可参照下一点【万能法】解决方案。此做法略过即可。</font>**

### 万能法【推荐此做法】
此解决方法，跑起来简单快捷高效。高版本也能跑，干脆粗暴。

步骤

1. 下载我给出的这个依赖包。

[node_modules.zip](https://www.yuque.com/attachments/yuque/0/2025/zip/32649796/1748597595688-a311b016-448a-4aed-aff6-615580479666.zip)

2. 下载回来以后，重新解压新的一份前端出来「**解压进一个没有中文的路径，这点是坑过很多人的**」，然后把下载回来的依赖包，解压在前端项目的目录下【与 src 目录同级】。
3. 直接执行 npm run dev 即可运行项目。【**注意，不用再执行 npm i 操作**】。因为下载回来的包，正是我导出来的前端项目的依赖包。

**digital envelope routines：：unsupported**

## 数据库密码忘记，重置步骤
:::color1
适用于 MySQL 5.7 和 8.0 版本  

:::

### MySQL 5.7系列重置 root 密码
#### 方法一：使用 `--skip-grant-tables` 模式
用管理员权限打开cmd之后，依次执行：

```plain
net stop mysql57「服务名请注意」
```

:::color1
注意：如果你的服务名不是 `mysql57`，请用 `services.msc` 查看。

:::

```plain
mysqld --skip-grant-tables --shared-memory --console
```

:::color1
**然后，保持此窗口运行**（不要关闭）。

:::

```plain
mysql -u root
```

```sql
USE mysql;
UPDATE user SET authentication_string=PASSWORD('你的新密码') WHERE User='root';
FLUSH PRIVILEGES;
EXIT;
```

:::color1
步骤五：关闭 `--skip-grant-tables` 窗口，即关闭在步骤二中不让关闭的这一个cmd。

:::

```plain
net start mysql57
```

### 2. MySQL 8.0 重置 root 密码
#### 方法一：使用 `--skip-grant-tables`（适用于忘记密码）
#### **步骤：**
:::color1
请确保你的服务名是不是mysql80，有些是mysql，通过services.msc查看。

:::

1. **停止 MySQL 服务**  

```plain
net stop mysql80「服务名请注意」
```

2. **以跳过权限模式启动 MySQL**  

```plain
mysqld --skip-grant-tables --shared-memory --console
```

    - **保持此窗口运行**。
3. **新开 CMD（管理员），无密码登录**  

```plain
mysql -u root
```

4. **更新密码（8.0 不再支持 **`PASSWORD()`**，改用 **`ALTER USER`**）**  

```sql
FLUSH PRIVILEGES;
ALTER USER 'root'@'localhost' IDENTIFIED BY '你的新密码';
EXIT;
```

    - 如果报错，尝试：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '你的新密码';
```

5. **关闭 **`--skip-grant-tables`** 窗口（按 **`Ctrl+C`**）**  
6. **重启 MySQL 服务**  

```plain
net start mysql80「服务名请注意」
```

---

### **方法二：使用 **`--init-file`**（推荐，安全）**
#### **步骤：**
:::color1
请确保服务名是mysql80，有些是mysql，可以通过services.msc查看。

:::

1. **停止 MySQL 服务**  

```plain
net stop mysql80「服务名请注意」
```

2. **创建 **`init-password.sql`** 文件（如 **`C:\mysql-init.sql`**）**  
写入：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY '你的新密码';
```

3. **以 **`--init-file`** 方式启动 MySQL**  

```plain
mysqld --init-file="C:\mysql-init.sql" --console
```

    - 等待几秒，直到看到 `Server startup complete`。
    - 按 `Ctrl+C` 终止进程。
4. **删除初始化文件**  

```plain
del C:\mysql-init.sql
```

5. **重启 MySQL 服务**  

```plain
net start mysql80「服务名请注意」
```

### 注意事项
1. **MySQL 服务名**  
    - 5.7 默认可能是 `mysql57`  
    - 8.0 默认可能是 `mysql80`  
    - 可通过 `services.msc` 或 `sc query` 查看。
2. **密码策略问题**  
    - 如果密码太简单，MySQL 8.0 可能拒绝修改，可临时禁用 `validate_password`：

```sql
SET GLOBAL validate_password.policy = LOW;
```

3. **认证方式问题（MySQL 8.0）**  
    - 如果客户端工具（如 Navicat）无法连接，可能需要改用 `mysql_native_password`：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '你的新密码';
```

### 验证是否成功
```plain
mysql -u root -p
```

输入新密码，能登录即表示重置成功。

## 前端登录进去发现图片不显示
:::color1
出现这种情况，解决方法就是只需要你自己维护过一次图片，就能正常使用。

:::

比如「用户管理」，点击页面上的「修改」功能，**在对应的功能区自己上传一次图片「图片上传框一点，上传即可」，后续图片就能用了。**

**所以出现这种，别觉得奇怪，因为缓存没了。**

:::success
以下是出现这种现象的原因。

咱们「手把手带敲」系列的项目图片资源，都是存放在后端缓存中的。咱们用的Web服务器是SpringBoot 内嵌 Tomcat 。

一般，Web项目在用到类似文件存储服务的时候，都要集成第三方云存储服务，要么用现成的像**阿里云、七牛云**这种，要么**自己搭建图床**「比如Minio」。

不管用哪一种，要么为空间付费花钱，要么整个系统技术实现过程复杂度直线上升。

所以，咱们系统采用的这种方式是有一些局限性的，好处就是不用花钱，不复杂。

只要在你自己的本机上维护过一次图片，后续就不会不显示了，除非你后续又自己手动把后端的项目缓存清楚了。即手动去清除了项目缓存：「maven ---〉clean」

:::
